# Специалист MX — эмулятор

Эмулятор радиолюбительского компьютера **«Специалист MX»** для Windows и Linux: окно
с экраном 384×256, отладчик и эмуляция всех устройств машины — ОЗУ, RAM- и ROM-диск,
клавиатура, программируемый таймер, контроллер дисковода и динамик. Процессор — на выбор:
**Intel 8080A** (КР580ВМ80А) или **Zilog Z80**. Тактовая частота меняется на ходу.

Справка по железу — на сайте [spetsialist-mx.zx-pk.ru](https://spetsialist-mx.zx-pk.ru/index.html):
базовая машина «Специалист» и доработка до «Специалиста MX».

## Как начать

1. Скачайте готовый релиз: папка `release_package` в этом репозитории или раздел
   [Releases](https://github.com/AVSh-Soft/specialist_mx/releases) на GitHub.
   В архиве — программа вместе с набором игр, утилит и образов дисков.
2. Распакуйте архив в любой каталог и запустите `specialist_mx.exe` (Windows).
   На Linux — `java -jar specialist_mx.jar` из того же каталога.
3. Откройте программу через «Файл → Открыть…» или кнопку «Открыть»: `.cpu`, `.rks`, `.rom`.
   Образы дискет подключаются через «Файл → Диск A / Диск B».
4. Клавиатуру, процессор и частоту выбирают в меню «Просмотр». Сброс — «Файл → Сбросить»
   или кнопка «Сбросить».

Программа читает `specialist_mx.ini` из своего каталога; в релизе там уже прописано
`RomFile = files_rom\spmx.rom` — ПЗУ, которое открывается при старте.

## Возможности

- Экран 384×256, 1 бит на точку, 12 Кбайт видеопамяти в области `0x9000`–`0xBFFF`;
  байт хранит 8 горизонтальных точек, адрес `0x9000 + y*32 + x/8`.
- **Цвет.** Код цвета пишется в порт `0xFFF8` и хранится в контроллере цвета: младший полубайт —
  цвет фона, старший — цвет изображения. 8 базовых цветов RGB расширяются до 16 битом яркости
  ([таблица цветности](https://spetsialist-mx.zx-pk.ru/index18.html)):

  | Код | Цвет       | Код | Цвет           |
  |-----|------------|-----|----------------|
  | 0   | чёрный     | 8   | тёмно-серый    |
  | 1   | синий      | 9   | ярко-синий     |
  | 2   | зелёный    | A   | ярко-зелёный   |
  | 3   | бирюзовый  | B   | ярко-бирюзовый |
  | 4   | красный    | C   | розовый        |
  | 5   | фиолетовый | D   | сиреневый      |
  | 6   | коричневый | E   | жёлтый         |
  | 7   | белый      | F   | ярко-белый     |

  Уже выведенное изображение при смене кода не перекрашивается: память цвета процессору
  недоступна, поэтому перекрасить экран можно только повторным выводом.
- Память: основная страница и до 8 страниц RAM-диска по 64 Кбайт, ROM-диск до 48 Кбайт.
  Страницы переключаются записью в `0xFFFC` (закрыть), `0xFFFD` (RAM-диск), `0xFFFE`
  (ROM-диск).
- Клавиатура — матрица 12 столбцов × 6 строк через КР580ВВ55 (`0xFFE0`), две раскладки.
  Соответствие клавиш ПК и машины — в разделе
  [«Клавиатура: клавиши PC и клавиши машины»](#клавиатура-клавиши-pc-и-клавиши-машины).
- Программируемый таймер КР580ВИ53 (`0xFFEC`), порт программирования (`0xFFE4`),
  контроллер НГМД КР1818ВГ93 (`0xFFE8`, `0xFFF0`), динамик на выходе таймера.
- **Переключение процессора** без потери состояния: общие регистры (`AF`, `BC`, `DE`, `HL`,
  `SP`, `PC`) переносятся на новое ядро, и программа продолжается с того же места.
- **Тактовая частота** — «Просмотр → Тактовая частота»: от `0.5` МГц до пиковой частоты
  конкретного ПК, шаг 100 кГц; кнопка «по умолчанию» возвращает `2` МГц (см.
  [«Тактовая частота»](#тактовая-частота)).
- **Отладчик** для обоих процессоров: регистры, флаги, дизассемблер, точки останова, шаг,
  шаг через вызов, «Run to cursor», поиск и правка памяти.

## Форматы файлов

| Формат | Что это                                           | Как загружается                             |
| ------ | ------------------------------------------------- | ------------------------------------------- |
| `.rom` | ПЗУ/монитор целиком                               | С адреса `0x0000`, затем запуск             |
| `.mon` | Монитор, адрес загрузки берётся из имени          | Сам при запуске `.cpu`, если монитор не тот |
| `.cpu` | Текстовый заголовок + данные `.i80`               | «Файл → Открыть»: адреса загрузки и старта  |
| `.rks` | Бинарный формат с заголовком и контрольной суммой | «Файл → Открыть»                            |
| `.odi` | Образ дискеты                                     | «Файл → Диск A / Диск B»                    |

Блок памяти сохраняется в `.cpu` и `.rks` через «Файл → Сохранить блок...».

## Настройки

Файл `specialist_mx.ini` в каталоге приложения, секция `[Config]`:

| Опция              | Смысл                                 |
| ------------------ | ------------------------------------- |
| `RomFile`          | ROM-файл, открытый при старте         |
| `Cpu`              | Активный процессор: `i8080` или `Z80` |
| `MainFormWidth`    | Ширина главного окна                  |
| `MainFormHeight`   | Высота главного окна                  |
| `DebugFrameWidth`  | Ширина окна отладчика                 |
| `DebugFrameHeight` | Высота окна отладчика                 |

Отсутствующее или неизвестное значение `Cpu` трактуется как `i8080`. Выбранная раскладка
клавиатуры не сохраняется: после сброса компьютера снова действует «Специалист MX».

## Клавиатура: клавиши PC и клавиши машины

Клавиатура машины — матрица 12 столбцов × 6 строк через КР580ВВ55 (`0xFFE0`–`0xFFE3`).
Строки читаются с порта B, первые четыре столбца выбираются портом C, остальные восемь —
портом A. Режим выбирается в меню «Просмотр → Клавиатура …».

`&#124;` — клавиша ПК. Если клавиша ПК не указана, нажимается одноимённая.

Строки `B6`–`B3` в обеих раскладках одинаковы. Цифровой блок (`NumPad`) дублирует цифровые
клавиши и знаки: `+` работает как `` ` ``, `*` как `=`, `/` как `/`, `-` как `-`, `.` как `.`.

**Что означают названия.** Расшифровка по разделу «1. Клавиатура» руководства RAMFOS
([скан `RAMFOS.djvu`](https://spetsialist-mx.zx-pk.ru/Docs/RAMFOS.djvu), Магнитогорск, 1992)
и [описанию интерфейсов ПК «Специалист MX»](https://spetsialist-mx.zx-pk.ru/index24.html):

| Клавиша    | Что делает                                                                                    |
| ---------- | --------------------------------------------------------------------------------------------- |
| ВК         | Разрешение, подтверждение выполнения команд и директив                                        |
| СТР        | Прерывание, отмена команды или директивы — как правило, внутри программы                      |
| АР2        | То же, что СТР, но на более высоком уровне: прерывает работу самой программы                  |
| РУС/LAT    | Переключение регистров символьных клавиш; постоянное нажатие замедляет вывод на экран         |
| НР         | Прерывает часть функций BIOS и на время нажатия меняет регистр; удержание — ускоренный ввод   |
| КОИ        | Переключение кодовой таблицы КОИ-7/КОИ-8; текущая видна в служебной строке цифрой `7` или `8` |
| F1 – F7    | Функции, переназначаемые программами пользователя и показываемые в нижней служебной строке    |
| F8         | Выбор плотности записи на ленту и типа принтера                                               |
| F9         | Включение и выключение режима эхопечати на принтер                                            |
| ПВ, ПС     | Перемещение курсора на строку вперёд / назад                                                  |
| `<=`, `=>` | Перемещение курсора влево / вправо                                                            |
| Ч.Ф, Б.Ф   | Служебные клавиши стандартного «Специалиста»                                                  |

**НР** — это `Shift`. В матрицу она не входит: нажатый `Shift` сбрасывает бит `PB1` порта B
(`0b1111_1101`), который программы читают при сканировании, и действует одинаково в обеих
раскладках.

**СТР** закреплена за клавишей `Delete`: у машины СТР — это стирание, что по смыслу совпадает.
Клавиши `Insert` в матрице нет, `Esc` в стандартной раскладке — это АР2 (`B2A6`).

**Коллизии символов ПК и машины.** Часть символов набирается на ПК и на машине по-разному:
`:` на ПК — это `Shift`+`;`, а у машины двоеточие в нижнем регистре (`B5A0`); круглые скобки
на ПК — `Shift`+`9` и `Shift`+`0`, а у машины `(` и `)` на клавишах `8` и `9`. Такие пары
не описываются таблицей масок, поэтому порт подбирает их по символу события и сам выставляет
или снимает признак `Shift`:

| Нажатие на ПК | Что получает программа                                   |
| ------------- | -------------------------------------------------------- |
| `Shift`+`;`   | `:` — клетка `B5A0`, признак `Shift` снят                |
| `Shift`+`9`   | `(` — клетка `B6A3`, признак `Shift` выставлен           |
| `Shift`+`0`   | `)` — клетка `B6A2`, признак `Shift` выставлен           |
| `Shift`+`7`   | `&` — клетка `B6A5`, `Shift` выставлен                   |
| `Shift`+`8`   | `*` — клетка `B5A0`, `Shift` выставлен                   |
| `Shift`+`6`   | `^` — клетка `B3C2`, `Shift` снят                        |
| `Shift`+`'`   | `"` — клетка `B6C1`, `Shift` выставлен                   |
| `Shift`+`=`   | `+` — клетка `B6C3`, `Shift` выставлен                   |
| `'`           | `'` — клетка `B6A4`, `Shift` выставлен (виртуальный)     |
| `=`           | `=` — клетка `B6A0`, `Shift` выставлен (виртуальный)     |
| `` ` ``       | `` ` `` — клетка `B3A3`, `Shift` выставлен (виртуальный) |
| `;`           | `;` — клетка `B6C3`, `Shift` снят                        |

`Shift`+`;` всегда даёт двоеточие, сколько бы раз `Shift` ни отпускали и ни нажимали снова;
клетку `B3A2` (`@`) это нажатие не выставляет — `@` на машине обозначает лицевую панель,
а не символ, набираемый с ПК.

**Русская раскладка хоста.** Раскладка определяется по символу события клавиатуры, поэтому
русский текст набирается без настроек в эмуляторе: русская `к` на клавише `R` даёт ту же
клетку `B5C0`, что латинская `K`. В карте русских букв 31 символ — без `ё`: её нет ни
на клавиатуре, ни в знакогенераторе машины. Служебные клавиши, цифры и стрелки от раскладки
не зависят.

**Маски в коде.** Позиция клавиши записана как `строка_столбцы`: `B7` — старший бит поля строк
(`0x80`), `C3` — старший бит поля столбцов `C3`–`C0` и `A7`–`A0` (`0x800`). Поэтому `B7C3` —
это `0x80_800`, `B2C3` — `0x04_800`, `B7A0` — `0x80_001`.

## Тактовая частота

Частота задаётся в меню «Просмотр → Тактовая частота»: слайдер с шагом 100 кГц и поле ввода
в МГц (принимаются точка и запятая), ниже — точное значение в герцах.

| Что                           | Значение                                          |
| ----------------------------- | ------------------------------------------------- |
| Частота по умолчанию          | `2` МГц                                           |
| Минимальная частота в диалоге | `0.5` МГц                                         |
| Шаг слайдера и округления     | 100 кГц                                           |
| Максимальная частота          | пиковая частота, которую вытягивает конкретный ПК |

Максимум не константа: генератор оценивает его по медиане длительности последних 1000 импульсов,
поэтому единичные «залипания» планировщика ОС максимум не занижают. Выше частоты по умолчанию
эмулятор идёт «насколько хватает ПК»: реальное время уже не выдерживается, и всё привязанное
к тактам — таймер, динамик, скорость диска — ускоряется вместе с процессором.

От частоты пересчитываются параметры динамика (`Speaker`) и время ожидания ответа контроллера
дисковода. При загрузке `.cpu`-файла, для которого нужен другой монитор, эмулятор на время
инициализации BIOS/монитора кратковременно поднимает частоту в 4 раза и возвращает прежнюю.

## Процессоры

**Intel 8080A (КР580ВМ80А).** Реализован документированный набор. Недокументированные коды
ведут себя как их документированные аналоги и показываются в дизассемблере строчными
(`jmp`, `call`, `ret`).

**Zilog Z80.** Реализован полный набор NMOS Z80 (Z0840004), включая недокументированные
команды и флаги: префиксы `CB`, `ED`, `DD`/`FD`, составные `DD CB d op`/`FD CB d op`, `SLL`,
обращение к половинам индексных регистров `IXH/IXL/IYH/IYL`, `IN F,(C)`, `OUT (C),0`,
альтернативный набор регистров (`EX AF,AF'`, `EXX`), внутренний регистр `MEMPTR` и регистр `Q`,
от которых зависят флаги `F5`/`F3` и поведение `SCF`/`CCF`.

**Чего нет:** режимы прерываний `IM 0`/`IM 1`/`IM 2` и вход `INT`/`NMI` не реализованы.
На «Специалисте MX» линия `/INT` не разведена (выход таймера идёт на динамик), поэтому
прерываний не получает ни один процессор; коды `IM` выполняются как `NOP` длиной два байта.
`RST n` — это вызов подпрограммы, он реализован.

**Отличие регистра `F`.** Бит 2 у Z80 — это `P/V` (переполнение в арифметике, чётность
в логических командах), у 8080A — только чётность. Программа для 8080A, проверяющая `PE`/`PO`
после арифметики, на Z80 получит другое условие перехода — это документированное поведение Z80.

## Сборка

Требуется JDK 8 (с JavaFX, если собираете под Linux) и Maven:

```bash
mvn -DskipTests clean package
```

Готовый JAR — `target/specialist_mx-<версия>.jar` (shade-plugin собирает зависимости внутрь);
под Windows дополнительно создаётся `.exe` через launch4j. Запуск:

```bash
java -jar target/specialist_mx-<версия>.jar
```

Каталог приложения — текущий рабочий каталог: из него читается `specialist_mx.ini` и в нём
ищется каталог `mon` с MON-файлами. `-DskipTests` указан намеренно: в `pom.xml` нет surefire,
а Maven подключает его по умолчанию и падает в офлайне; тестовые классы при этом компилируются.

## Проверки

Прогон на реальных программах-эталонах:

| Класс                    | Что проверяет                                                              |
| ------------------------ | -------------------------------------------------------------------------- |
| `CpuI8080Test`           | `8080pre`, `8080`, `tst8080`, `cputest`, `8080exm` (CRC по блокам)         |
| `CpuZ80Test`             | `zexdoc`, `zexall`, `z80type` через ту же CP/M-эмуляцию                    |
| `CPUZ80SelfTest`         | Точечные сценарии `CpuZ80`: флаги, префиксы, регистры, ловушки             |
| `DisAsmSelfTest`         | Оба дизассемблера: длины, тексты, заполнение буфера таблицы отладчика      |
| `KeyboardLayoutSelfTest` | Раскладки клавиатуры по клеткам матрицы и очистка буфера при потере фокуса |

Тесты сравнивают весь вывод программы с эталоном, поэтому проверяют и результат, и отсутствие
лишних сообщений. `zexall` маскирует флаги константой `0D7h`, то есть биты `F5`/`F3` не проверяет —
их ловит только `z80type` (эталон NMOS Z80: `XF/YF: FF`, `XF/YF flags test: C000C000`).
`CpuZ80Test` содержит два тяжёлых теста (`zexdoc`, `zexall`) — около 20 минут каждый.

`CPUZ80SelfTest`, `DisAsmSelfTest` и `KeyboardLayoutSelfTest` — обычные `main`-классы:

```bash
java -cp target/classes:target/test-classes:<зависимости> \
     ru.avsh.specialist.mx.units.CPUZ80SelfTest
```

Итоговую приёмку даёт ручной прогон: экран, клавиатура, диск, звук, отладчик. Автоматические
проверки его не заменяют.

## Структура проекта

```
src/main/java/ru/avsh/specialist/mx/
├── Main.java                  Точка входа

│   ├── CpuI8080.java          Ядро Intel 8080A (КР580ВМ80А)
│   ├── CpuZ80.java            Ядро Zilog Z80
│   ├── ClockSpeedGenerator.java  Тактовый генератор (поток), тактовая частота
│   ├── Speaker.java           Динамик (пересчитывается при смене частоты)
│   ├── memory/                Диспетчер памяти и устройства
│   └── types/                 Контракты: CpuCore, CpuDebugCore, MemoryUnit, ...
├── gui/
│   ├── SpMxApplication.java   Главное окно JavaFX, меню

```

контекст для спецификаций — в `openspec/project.md` и `openspec/specs/`.
