# Специалист MX — эмулятор

Эмулятор радиолюбительского компьютера **«Специалист MX»** для Windows и Linux. Повторяет
машину целиком: экран 384×256, ОЗУ, RAM- и ROM-диск, клавиатура, программируемый таймер,
контроллер дисковода, динамик. Процессор — **Intel 8080A** (КР580ВМ80А) или **Zilog Z80**,
переключается из меню без перезапуска программы. Тактовая частота меняется на ходу. Внутри
ещё есть отладчик с дизассемблером для обоих процессоров.

Что такое базовая машина «Специалист» и как её доработали до «Специалиста MX» — на сайте
[spetsialist-mx.zx-pk.ru](https://spetsialist-mx.zx-pk.ru/index.html).

## Как начать

1. Скачайте архив: `release_package/SPMX_java_*.zip` в этом репозитории или раздел
   [Releases](https://github.com/AVSh-Soft/specialist_mx/releases) на GitHub. Внутри —
   `specialist_mx.exe`, `specialist_mx.ini`, ПЗУ в `files_rom`, мониторы в `mon`, набор игр,
   утилит и образов дисков в `files_cpu` и `emu_tests`.
2. Распакуйте архив целиком в любой каталог. Важно, чтобы `specialist_mx.ini` и `files_rom`
   лежали рядом с `specialist_mx.exe`: ini читается из каталога приложения (в Windows — из
   каталога, откуда запущена программа).
3. Запустите `specialist_mx.exe`. Собранный из исходников JAR на Linux запускается так:
   `java -jar specialist_mx.jar`. Если внешний ПЗУ из `files_rom` не найден, эмулятор берёт
   встроенный `spmx.rom`.
4. Откройте программу: кнопка «Открыть» или «Файл → Открыть…». Подойдут `.cpu`, `.rks`,
   `.rom`, `.mon`, а образ дискеты `.odi` эмулятор спросит, в какой дисковод вставить.
5. Клавиатуру, процессор и частоту выбирают в меню «Просмотр». Сброс — «Файл → Сбросить»
   или кнопка «Сбросить».

При загрузке `.cpu` или `.rks` эмулятор показывает адреса и предлагает два варианта:
«Загрузить и запустить» или «Только загрузить». Если программе нужен другой монитор, он
подгружается автоматически — сначала из каталога файла, потом из `mon`.

Две клавиши удобно запомнить сразу: **`Pause`** останавливает и снова запускает машину,
в заголовке окна появляется «(пауза)»; **`Scroll Lock`** открывает отладчик.

### Состояние CPU/RAM

«Просмотр → Состояние CPU/RAM» открывает окно «Информация» с тремя блоками текста. Машина
на время вывода останавливается, чтобы показать согласованный снимок, после чего продолжает
работу.

- **Частота процессора** в МГц, например `2,0МГц`.
- **Значения регистров.** У Z80 — `SZ5H3PNC`, `A`, `B`, `C`, `D`, `E`, `H`, `L`, `IX`, `SP`,
  `PC`; у 8080A — `SZ0A0P1C` и то же без `IX`. Флаги показаны двоичным числом. В отладчике
  те же позиции у 8080A подписаны `SZ?A?P?C`: `?` — биты, которые у процессора не являются
  флагами, их кнопки недоступны.
- **Память с адреса PC** — первые пять байт по текущему `PC`.
- **Информация о памяти:** общий объём (RAM + RAM-диск + ROM-диск) в килобайтах (при полном
  наборе — `623,4375Кб`), число страниц и номер активной страницы.

Заголовок «Состояние CPU/RAM» шире содержимого: карты адресного пространства в окне нет,
только сводка регистров и размеров памяти. Карта — в разделе
[«Карта адресов»](#карта-адресов).

## Возможности

- **Экран** 384×256, 1 бит на точку. Видеопамять — 12 Кбайт в области `0x9000`–`0xBFFF`:
  байт хранит 8 горизонтальных точек, адрес байта `0x9000 + y*32 + x/8`.
- **Цвет.** Код цвета пишется в порт `0xFFF8`: младший полубайт — цвет фона, старший — цвет
  изображения. 8 базовых цветов RGB расширяются до 16 битом яркости
  ([таблица цветности](https://spetsialist-mx.zx-pk.ru/index18.html)):

  | Код   | Цвет         | Код   | Цвет             |
  | ----- | ------------ | ----- | ---------------- |
  | 0     | чёрный       | 8     | тёмно-серый      |
  | 1     | синий        | 9     | ярко-синий       |
  | 2     | зелёный      | A     | ярко-зелёный     |
  | 3     | бирюзовый    | B     | ярко-бирюзовый   |
  | 4     | красный      | C     | розовый          |
  | 5     | фиолетовый   | D     | сиреневый        |
  | 6     | коричневый   | E     | жёлтый           |
  | 7     | белый        | F     | ярко-белый       |

  Смена кода перекрашивает только то, что будет выведено дальше. Уже нарисованное на экране
  остаётся: память цвета процессору недоступна, поэтому картинку можно перекрасить только
  повторным выводом.
- **Память.** Основная страница и до 8 страниц RAM-диска по `0xFFC0` байт (65 472), ROM-диск
  до 48 Кбайт. Страницы переключаются записью в `0xFFFC` (закрыть), `0xFFFD` (RAM-диск),
  `0xFFFE` (ROM-диск).
- **Клавиатура** — матрица 12 столбцов × 6 строк через КР580ВВ55 (`0xFFE0`), две раскладки.
  Полное соответствие клавиш ПК и машины — в разделе
  [«Клавиатура: клавиши PC и клавиши машины»](#клавиатура-клавиши-pc-и-клавиши-машины).
- **Периферия:** программируемый таймер КР580ВИ53 (`0xFFEC`), порт программирования
  (`0xFFE4`), контроллер НГМД КР1818ВГ93 (`0xFFE8`, `0xFFF0`), динамик на выходе таймера.
- **Переключение процессора** без потери состояния. Общие регистры (`AF`, `BC`, `DE`, `HL`,
  `SP`, `PC`) переносятся на новое ядро, и программа продолжается с того же места. Пока
  открыт отладчик, переключение заблокировано.
- **Тактовая частота** — от `0.5` МГц до пиковой частоты конкретного ПК, шаг 100 кГц.
  Подробности — в разделе [«Тактовая частота»](#тактовая-частота).
- **Отладчик** для обоих процессоров: регистры и флаги, дизассемблер, пошаговое исполнение,
  шаг через вызов, запуск до курсора, поиск и правка памяти, точки останова.

## Форматы файлов

| Формат | Что это                                           | Как загружается                             |
| ------ | ------------------------------------------------- | ------------------------------------------- |
| `.rom` | ПЗУ/монитор целиком                               | С адреса `0x0000`, затем запуск             |
| `.mon` | Монитор, адрес загрузки берётся из имени          | Сам при запуске `.cpu`, если монитор не тот |
| `.cpu` | Текстовый заголовок + данные `.i80`               | «Файл → Открыть»: адреса загрузки и старта  |
| `.rks` | Бинарный формат с заголовком и контрольной суммой | «Файл → Открыть»                            |
| `.odi` | Образ дискеты                                     | «Файл → Диск A / Диск B»                    |

`.cpu` и `.i80` живут парой. В `.cpu` три строки: адрес загрузки, адрес запуска и имя
монитора — все в шестнадцатеричном виде без префикса `0x`, а сами данные лежат рядом,
в `.i80`. Имя `.mon` тоже несёт смысл: `mx_d400.mon` загружается с адреса `0xD400`.
В релизном архиве в `mon` лежат мониторы `L1`, `L2`, `m1`–`m3`, `mp`, `mx`, `rk` и `b1`–`b3`.

Область памяти сохраняется в `.cpu` или `.rks` через «Файл → Сохранить блок...» или кнопку
«Сохранить». В диалоге три поля: «Начало» и «Конец» — границы блока, «Старт» — адрес,
с которого программа начнёт выполняться после загрузки. «Старт» пишется во вторую строку
заголовка `.cpu` и для `.rks` не используется. Рядом с сохранённым `.cpu` появляется парный
`.i80` с данными.

Читается активная страница памяти: чтобы сохранить блок из RAM-диска, сначала переключите
на неё страницу. Для страницы доступны адреса `0x0000`–`0xFFBF`; байты `0xFFC0`–`0xFFFF`
`.cpu` и `.rks` не сохраняют.

## Настройки

Файл `specialist_mx.ini` в каталоге приложения, секция `[Config]`:

| Опция              | Смысл                                 |
| ------------------ | ------------------------------------- |
| `RomFile`          | ROM-файл, открытый при старте         |
| `Cpu`              | Активный процессор: `i8080` или `Z80` |
| `MainFormWidth`    | Ширина главного окна                  |
| `MainFormHeight`   | Высота главного окна                  |
| `DebugFrameWidth`  | Ширина окна отладчика                 |
| `DebugFrameHeight` | Высота окна отладчика                 |

В релизе `RomFile = files_rom\spmx.rom`, поэтому при старте загружается ПЗУ из этой папки.
Путь записывается относительно каталога приложения. Если файла нет, берётся встроенный ПЗУ.
Неизвестное или отсутствующее значение `Cpu` считается как `i8080`. Размеры главного окна
запоминаются при выходе, размеры отладчика — при его закрытии. Выбранная раскладка клавиатуры
не сохраняется: после сброса компьютера снова действует «Специалист MX».

## Клавиатура: клавиши PC и клавиши машины

Клавиатура машины — матрица 12 столбцов × 6 строк через КР580ВВ55 (`0xFFE0`–`0xFFE3`).
Строки читаются с порта B, первые четыре столбца выбираются портом C, остальные восемь —
портом A. Раскладка выбирается в меню «Просмотр → Клавиатура …».

В клетке таблицы записано название клавиши на лицевой панели машины, а через `&#124;` —
клавиша ПК. Если клавиша ПК не указана, нажимается одноимённая.

Строки `B6`–`B3` в обеих раскладках одинаковы, различается только `B2`. Цифровой блок
(`NumPad`) дублирует цифровые клавиши и знаки: `+` работает как `` ` ``, `*` как `=`, `/`
как `/`, `-` как `-`, `.` как `.`.

**Что означают названия.** Расшифровка по разделу «1. Клавиатура» руководства RAMFOS
([скан `RAMFOS.djvu`](https://spetsialist-mx.zx-pk.ru/Docs/RAMFOS.djvu), Магнитогорск, 1992)
и [описанию интерфейсов ПК «Специалист MX»](https://spetsialist-mx.zx-pk.ru/index24.html):

| Клавиша    | Что делает                                                                                    |
| ---------- | --------------------------------------------------------------------------------------------- |
| ВК         | Разрешение, подтверждение выполнения команд и директив                                        |
| СТР        | Прерывание, отмена команды или директивы — как правило, внутри программы                      |
| АР2        | То же, что СТР, но на более высоком уровне: прерывает работу самой программы                  |
| РУС/LAT    | Переключение регистров символьных клавиш; постоянное нажатие замедляет вывод на экран         |
| НР         | Прерывает часть функций BIOS и на время нажатия меняет регистр; удержание — ускоренный ввод   |
| КОИ        | Переключение кодовой таблицы КОИ-7/КОИ-8; текущая видна в служебной строке цифрой `7` или `8` |
| F1 – F7    | Функции, переназначаемые программами пользователя и показываемые в нижней служебной строке    |
| F8         | Выбор плотности записи на ленту и типа принтера                                               |
| F9         | Включение и выключение режима эхопечати на принтер                                            |
| ПВ, ПС     | Перемещение курсора на строку вперёд / назад                                                  |
| `<=`, `=>` | Перемещение курсора влево / вправо                                                            |
| Ч.Ф, Б.Ф   | Служебные клавиши стандартного «Специалиста»                                                  |

**НР** — это `Shift`. В матрицу она не входит: нажатый `Shift` сбрасывает бит `PB1` порта B
(`0b1111_1101`), который программы читают при сканировании, и действует одинаково в обеих
раскладках.

**СТР** закреплена за клавишей `Delete`: у машины СТР — это стирание, что по смыслу совпадает.
Клавиши `Insert` в матрице нет, `Esc` в стандартной раскладке — это АР2 (`B2A6`).

**Коллизии символов ПК и машины.** Часть символов набирается на ПК и на машине по-разному:
`:` на ПК — это `Shift`+`;`, а у машины двоеточие в нижнем регистре (`B5A0`); круглые скобки
на ПК — `Shift`+`9` и `Shift`+`0`, а у машины `(` и `)` на клавишах `8` и `9`. Такие пары
не описываются таблицей масок, поэтому порт подбирает их по символу события и сам выставляет
или снимает признак `Shift`:

| Нажатие на ПК | Что получает программа                                   |
| ------------- | -------------------------------------------------------- |
| `Shift`+`;`   | `:` — клетка `B5A0`, признак `Shift` снят                |
| `Shift`+`9`   | `(` — клетка `B6A3`, признак `Shift` выставлен           |
| `Shift`+`0`   | `)` — клетка `B6A2`, признак `Shift` выставлен           |
| `Shift`+`7`   | `&` — клетка `B6A5`, `Shift` выставлен                   |
| `Shift`+`8`   | `*` — клетка `B5A0`, `Shift` выставлен                   |
| `Shift`+`6`   | `^` — клетка `B3C2`, `Shift` снят                        |
| `Shift`+`'`   | `"` — клетка `B6C1`, `Shift` выставлен                   |
| `Shift`+`=`   | `+` — клетка `B6C3`, `Shift` выставлен                   |
| `'`           | `'` — клетка `B6A4`, `Shift` выставлен (виртуальный)     |
| `=`           | `=` — клетка `B6A0`, `Shift` выставлен (виртуальный)     |
| `` ` ``       | `` ` `` — клетка `B3A3`, `Shift` выставлен (виртуальный) |
| `;`           | `;` — клетка `B6C3`, `Shift` снят                        |

`Shift`+`;` не выставляет клетку `B3A2` (`@`): `@` на машине обозначает лицевую панель,
а не символ, набираемый с ПК.

**Русская раскладка хоста.** Раскладка определяется по символу события клавиатуры, поэтому
русский текст набирается без настроек в эмуляторе: русская `к` на клавише `R` даёт ту же
клетку `B5C0`, что латинская `K`. В карте русских букв 31 символ — без `ё`: её нет ни
на клавиатуре, ни в знакогенераторе машины. Служебные клавиши, цифры и стрелки от раскладки
не зависят.

**Маски в коде.** Позиция клавиши записана как `строка_столбцы`: `B7` — старший бит поля строк
(`0x80`), `C3` — старший бит поля столбцов `C3`–`C0` и `A7`–`A0` (`0x800`). Поэтому `B7C3` —
это `0x80_800`, `B2C3` — `0x04_800`, `B7A0` — `0x80_001`.

## Тактовая частота

Частота задаётся в меню «Просмотр → Тактовая частота»: слайдер с шагом 100 кГц и поле ввода
в МГц (принимаются точка и запятая), ниже — точное значение в герцах.

| Что                           | Значение                                          |
| ----------------------------- | ------------------------------------------------- |
| Частота по умолчанию          | `2` МГц                                           |
| Минимальная частота в диалоге | `0.5` МГц                                         |
| Шаг слайдера и округления     | 100 кГц                                           |
| Максимальная частота          | пиковая частота, которую вытягивает конкретный ПК |

Максимум не постоянный. Генератор оценивает его по медиане длительности последних 1000
импульсов, поэтому единичные «залипания» планировщика ОС максимум не занижают. Выше частоты
по умолчанию эмулятор идёт «насколько хватает ПК»: реальное время уже не выдерживается, и всё
привязанное к тактам — таймер, динамик, скорость диска — ускоряется вместе с процессором.

От частоты зависят параметры динамика (`Speaker`) и время ожидания ответа контроллера
дисковода. Когда `.cpu`-файлу нужен другой монитор, эмулятор поднимает частоту в 4 раза
на время его инициализации и возвращает прежнюю.

## Процессоры

**Intel 8080A (КР580ВМ80А).** Реализован документированный набор. Недокументированные коды
ведут себя как их документированные аналоги и показываются в дизассемблере строчными
(`jmp`, `call`, `ret`).

**Zilog Z80.** Реализован полный набор NMOS Z80 (Z0840004), включая недокументированные
команды и флаги: префиксы `CB`, `ED`, `DD`/`FD`, составные `DD CB d op`/`FD CB d op`, `SLL`,
обращение к половинам индексных регистров `IXH/IXL/IYH/IYL`, `IN F,(C)`, `OUT (C),0`,
альтернативный набор регистров (`EX AF,AF'`, `EXX`), внутренний регистр `MEMPTR` и регистр `Q`,
от которых зависят флаги `F5`/`F3` и поведение `SCF`/`CCF`. Точность набора проверена
программами `zexdoc`, `zexall` и `z80type` — они же есть в тестах репозитория.

Что не реализовано и почему — режимы прерываний `IM 0`/`IM 1`/`IM 2` и вход `INT`/`NMI`
отсутствуют. На «Специалисте MX» линия `/INT` не разведена — выход таймера идёт на динамик, —
поэтому прерываний не получает ни один процессор, а коды `IM` выполняются как `NOP`
длиной два байта. `RST n` — это обычный вызов подпрограммы, он работает.

Регистр `F` у процессоров устроен по-разному. Бит 2 у Z80 — это `P/V` (переполнение
в арифметике, чётность в логических командах), у 8080A — только чётность. Программа
для 8080A, проверяющая `PE`/`PO` после арифметики, на Z80 уйдёт по другой ветке: это
документированное поведение Z80, а не ошибка эмулятора.

## Отладчик

Отладчик открывается из меню «Просмотр → Запуск отладчика», кнопкой «Отладчик» или клавишей
`Scroll Lock` (на ноутбуках без отдельной клавиши — через `Fn`).

**Что в окне**

- Слева — дизассемблер: колонки «Адрес», байты команды и текст. Текущая команда (`PC`)
  подсвечена, ловушки отмечены флажком, курсор помечен в колонке «Код».
- Справа сверху — строка флагов (`SZ5H3PNC` у Z80, `SZ?A?P?C` у 8080A). Щелчок по флагу
  выставляет или сбрасывает его.
- Ниже — таблица регистровых пар (у Z80 `AF`, `AF'`, `BC`, `BC'`, `DE`, `DE'`, `HL`, `HL'`,
  `IX`, `IY`, `SP`, `PC`). Значение можно ввести прямо в таблице, изменённые значения
  подсвечены.
- Правее — стек: адрес `(SP)`, следующие пары и значения.
- Ещё правее — список ловушек: страница и адрес. `Delete` убирает выбранную, `Clear` —
  все; двойной щелчок по ловушке переходит к её коду.
- Строка «CPU работает в: …» и два списка — какой странице памяти принадлежит код (`←`)
  и данные (`↓`): `RAM`, `RAM disk 1…8`, `ROM disk`.
- Внизу — окно данных выбранной страницы: адрес и 16 байт в шестнадцатеричном виде
  плюс те же байты символами.

**Как это работает**

- **Ловушка** ставится флажком в первой колонке дизассемблера и снимается повторным щелчком.
  Ловушка привязана к странице памяти: та же самая строка на другой странице не остановит.
  При достижении ловушки открывается это окно.
- **Типовая работа:** поставить ловушки, нажать `OK` — программа начнёт выполняться
  и остановится на первой из них. Крестик окна сохраняет регистры так же, как `OK`, но не
  запоминает для следующего открытия страницу и выделение в окне данных.
- **Step** выполняет одну команду. **Step Over** делает то же, но вызов подпрограммы
  `CALL`/`CALL cc`/`RST` пропускает целиком: ставит временную ловушку на следующий адрес
  и выполняет программу до неё. **Run to cursor** переводит `PC` на адрес под курсором.

| Кнопка / клавиша | Что делает                                        |
| ---------------- | -------------------------------------------------- |
| `F6` Step        | Выполнить одну команду                             |
| `F7` Step Over   | Выполнить команду, не заходя внутрь вызова         |
| Run to cursor    | Запустить код с адреса, на котором стоит курсор    |
| Go to / To PC    | Перейти к адресу / вернуться к текущему `PC`       |
| Find             | Найти байты или строку в странице памяти           |
| Select           | Выделить блок памяти                               |
| Save             | Сохранить выделенный диапазон данных в файл        |
| Load             | Загрузить файл в страницу памяти с адреса курсора  |
| Delete / Clear   | Удалить выбранную ловушку / все ловушки            |
| OK               | Закрыть отладчик и продолжить выполнение программы |

Пока отладчик открыт, переключить процессор нельзя.

**Выделение закреплено за страницей.** В окне данных у каждой страницы (основная память,
`RAM disk 1…8`, `ROM disk`) своё выделение. При переключении страницы в списке `↓` выделение
остаётся за покидаемой страницей, а на новой показывается её собственное; если у страницы
выделения ещё нет, выделена одна ячейка с адресом `0x0000`. Возврат на страницу
восстанавливает её диапазон, а при закрытии и повторном открытии отладчика выделения всех
страниц восстанавливаются вместе со страницей: курсор встаёт на начало выделения показанной
страницы (или на `0x0000`, если у неё выделения не было).

**Save** (`Alt+V`) выгружает на диск байты страницы, выбранной в списке страниц данных
(основная память, RAM-диск или ROM-диск), по адресам от начала до конца выделения таблицы
просмотра данных включительно. Выделение задаётся мышью или кнопкой «Select»; сохраняется
выделение только показанной страницы — диапазон, оставшийся на другой странице, в файл не
попадает. Если в показанной странице ничего не выделено или выделена всего одна ячейка,
отладчик сообщает, что диапазон не выделен, и файловый диалог не открывает. Файл содержит
только байты памяти, без заголовка; если расширение не задано, дописывается `.bin`. Форматы
«Сохранить блок...» (`.cpu`, `.i80`, `.rks`) с заголовками эта кнопка не использует.

**Load** (`Alt+L`) читает выбранный файл и записывает его байты в страницу, выбранную в
списке страниц данных, начиная с адреса под курсором в таблице данных. Файл можно выбрать
любой, без ограничения по типу; в заголовке файлового диалога указаны адрес и страница
назначения. Остаток страницы не затирается — файл пишется ровно по своим адресам.

Перед записью отладчик проверяет размер файла (он запрашивается у файловой системы, поэтому
случайно выбранный огромный образ не читается и не роняет приложение):

- основной и RAM-дисковые страницы занимают `0x0000`–`0xFFBF`: файл, выходящий за `0xFFBF`,
  не загружается, отладчик сообщает размер файла, начальный адрес и последний допустимый
  адрес;
- адреса `0xFFC0`–`0xFFFF` принадлежат окну обмена страницами и портам устройств, а не
  памяти, — файл, который в них заходит, не загружается, и сообщение об этом отличается от
  сообщения о переполнении страницы;
- область экрана `0x9000`–`0xBFFF` запретом не считается: данные пишутся в неё как в обычную
  память страницы.

В ROM-диск загрузка не выполняется — отладчик сообщает об этом и не открывает файловый
диалог. Если что-то не прошло проверку (выбран каталог, файл не помещается, файл не читается),
содержимое страницы памяти не меняется: ни один байт не записывается.

## Сборка

Требуется JDK 8 (с JavaFX, если собираете под Linux) и Maven:

```bash
mvn -DskipTests clean package
```

Готовый JAR — `target/specialist_mx-<версия>.jar`; shade-plugin вкладывает зависимости внутрь,
поэтому JAR запускается сам по себе. Под Windows сборка дополнительно создаёт
`target/specialist_mx.exe` через launch4j. Запуск:

```bash
java -jar target/specialist_mx-<версия>.jar
```

Каталог приложения — текущий рабочий каталог: из него читается `specialist_mx.ini` и в нём
ищется каталог `mon` с MON-файлами. `-DskipTests` указан намеренно: в `pom.xml` нет surefire,
а Maven подключает его по умолчанию и падает в офлайне; тестовые классы при этом компилируются.

## Проверки

Прогон на реальных программах-эталонах:

| Класс                    | Что проверяет                                                              |
| ------------------------ | -------------------------------------------------------------------------- |
| `CpuI8080Test`           | `8080pre`, `8080`, `tst8080`, `cputest`, `8080exm` (CRC по блокам)         |
| `CpuZ80Test`             | `zexdoc`, `zexall`, `z80type` через ту же CP/M-эмуляцию                    |
| `CPUZ80SelfTest`         | Точечные сценарии `CpuZ80`: флаги, префиксы, регистры, ловушки             |
| `DisAsmSelfTest`         | Оба дизассемблера: длины, тексты, заполнение буфера таблицы отладчика      |
| `KeyboardLayoutSelfTest` | Раскладки клавиатуры по клеткам матрицы и очистка буфера при потере фокуса |

Тесты сравнивают весь вывод программы с эталоном, поэтому ловят и неверный результат, и лишние
сообщения. `zexall` маскирует флаги константой `0D7h`, то есть биты `F5`/`F3` не проверяет —
их ловит только `z80type` (эталон NMOS Z80: `XF/YF: FF`, `XF/YF flags test: C000C000`).
`CpuZ80Test` содержит два тяжёлых теста (`zexdoc`, `zexall`) — около 20 минут каждый.

`CPUZ80SelfTest`, `DisAsmSelfTest` и `KeyboardLayoutSelfTest` — обычные `main`-классы:

```bash
java -cp target/classes:target/test-classes:<зависимости> \
     ru.avsh.specialist.mx.units.CPUZ80SelfTest
```

Итоговую приёмку даёт ручной прогон: экран, клавиатура, диск, звук, отладчик. Автоматические
проверки его не заменяют.
